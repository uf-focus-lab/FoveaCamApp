# Ring code — the MirrorLink optical frame encoding

The on/off pattern a free-running emitter blinks during ONE MirrorLink scan revolution,
and how a fovea frame that integrates exactly that revolution is read back. The emitter
side (any MCU or LED driver) and the reader side (`@lib/ring-code` + the `ring` vision
kernel) are both bound by this page. Conformance vectors: `docs/schema/codec/ring-code-vectors.json`
(generated by the Python reference, pinned by `ring-code.test.ts`). Behavior of the app
around the reader: `mirror-link.md` §reader.

## Physical model {#model}

MirrorLink drives both fovea mirrors around a circle at `scan_hz` and overrides each
fovea's exposure to one revolution (`mirror-link.md` §exposure). Time within the emitter's
cycle therefore maps to ANGLE along a ring in the fovea frame. The emitter's cycle MUST
equal the scan period (or divide it by a small integer): the ring is then a faithful cyclic
picture of one cycle and the frame's exposure seam is invisible. Three things are unknown
to the reader and the code is designed so none of them matters: the rotation (emitter phase
vs. scan phase), the reading direction (scan sense × mirror orientation), and the seam
position. Angular speed along the ring is not assumed uniform.

A **chip** is one emitter time slot. The chip duration is `T / chips_per_frame`, so it
DEPENDS ON THE MESSAGE LENGTH — the reader never assumes a chip arc; it measures it from
the leader on every frame.

## Frame layout {#frame}

One frame per cycle, transmitted MSB-first, repeated forever by the emitter:

```
[ GAP ][ LEADER ][ Manchester( LEN:8 | DATA: LEN bytes | CRC8:8 ) ]
   3       8                 16·(LEN + 2) chips
```

| Field | Chips | Value | Role |
|---|---|---|---|
| GAP | 3 | `000` | Frame boundary: Manchester data never holds 3 OFF chips. Also the terminator of the previous frame. |
| LEADER | 8 | `1111 0 11 0` | Start of sequence: the only 4-chip ON run on the ring; asymmetric, so the reading direction is decidable; its edges are the clock reference. |
| LEN | 16 | Manchester(8 bits) | Byte count of DATA, 0–255. Cross-checks the bit count the gap terminates. |
| DATA | 16·LEN | Manchester(8·LEN bits) | Payload, bytes in order, each MSB-first. |
| CRC8 | 16 | Manchester(8 bits) | CRC-8 over the LEN and DATA **bits** (not chips). |

**Manchester:** bit `1` → chips `1 0` (ON then OFF); bit `0` → chips `0 1`. Consequences the
reader relies on: every bit has a mid-bit transition (self-clocking), runs never exceed 2
chips (so the GAP and the LEADER burst are unique), and the frame is DC-balanced (constant
mean brightness, so a single threshold serves the whole ring).

**CRC-8:** polynomial `0x07` (x⁸ + x² + x + 1), init `0x00`, bit-serial MSB-first over the
LEN then DATA bits, no reflection, no final XOR. `crc8(LEN=0) = 0x00`. (The TypeScript
`crc8(bits)` returns the 8-bit REGISTER; the Python reference below returns its bits.)

Frame length in chips is `11 + 16·(LEN + 2)`. An empty message is 43 chips.

**Reference encoder** (Python; the TypeScript `encodeFrame` in `@lib/ring-code` is
byte-identical and is what the vectors pin):

```python
GAP, LEADER = [0,0,0], [1,1,1,1,0,1,1,0]
def crc8(bits):
    reg = 0
    for b in bits:
        fb = ((reg >> 7) & 1) ^ b
        reg = ((reg << 1) & 0xFF) ^ (0x07 if fb else 0)
    return [(reg >> i) & 1 for i in range(7, -1, -1)]
bits = lambda v, n: [(v >> i) & 1 for i in range(n - 1, -1, -1)]
manchester = lambda bs: [c for b in bs for c in ((1, 0) if b else (0, 1))]
def encode(data: bytes):
    payload = bits(len(data), 8) + [b for x in data for b in bits(x, 8)]
    return GAP + LEADER + manchester(payload + crc8(payload))
```

## Emitter budget {#budget}

The reader resolves a chip only if its arc is wider than the blurred dot. With ring
circumference `C` (fovea px, `2π · focal_fovea · tan(scan_amp)`) and dot diameter `d`
(fovea px, rig-measured), the emitter must keep

```
chips_per_frame · k · d  ≤  C        (k = 1.5 resolution margin, rig-tunable)
max LEN  =  floor( (C / (k·d) − 43) / 16 )
```

A message over budget is refused by the reader (`below resolution`), never partially read.
Longer payloads are split across cycles by the emitter (a DATA-level index byte is the
emitter's convention; the frame format does not change). Chip timing on the emitter:
`chip_us = 1e6 / (scan_hz · chips_per_frame)`.

## Reader {#reader}

Source: `app/lib/ring-code.ts` (pure decoder over a binary ring sample array — Vue-free,
core-free, unit-tested) and `app/orchestrator/ring-kernel.ts` (the vision-worker kernel
that turns a fovea frame into that array and back-annotates the result).

### Ring extraction (kernel)

1. **Bright mask**: pixels above `dark + BRIGHT_FRACTION · (peak − dark)` of the frame's
   luminance (BGRA → max channel), computed on a 2× decimated copy.
2. **Circle fit**: algebraic least-squares (Kåsa) over the mask, then two robust
   re-fits discarding points whose radial residual exceeds 3σ. Reject (`no ring`) if fewer
   than `MIN_RING_POINTS` inliers, radius below `MIN_RADIUS_PX`, or the inliers occupy
   under half the angular bins (72 × 5°) — a dot, not a ring. Output `circle {x, y, r}` in
   fovea px (the fit runs on the decimated mask; the circle is scaled back).
3. **Angular profile**: `N = clamp(round(2π·r), 512, 4096)` samples at angles
   `θ_i = 2π·i/N` (image coordinates, +x → +y clockwise on screen), each the mean of 3
   radial taps at `r − 1.5, r, r + 1.5` px (bilinear). Threshold at the midpoint of the
   profile's 5th and 95th percentiles → the binary ring `s[0..N)`.

### Decode (`decodeRing(s)`)

1. **Median-3** (circular) — a one-sample dropout (the exposure seam, speckle) cannot fake an edge.
2. **Run-length encode** the circular array.
3. **Leader search** (start of sequence): an ON run of length `L` preceded, in reading
   order, by an OFF run of ≥ 2.5 chip-estimates; chip estimate `spc = L/4`; verify the tail
   `0 11 0` at chip centers. Refine `spc` over the 5-chip span from the burst start to the
   `11` run start. Tried in the forward direction, then on the reversed array; the
   asymmetric tail matches exactly one. No match in either → `no leader`.
4. **Resolution guard**: `spc < MIN_CHIP_PX` → `below resolution` (the emitter is over
   budget or the amplitude too small; nothing to recover).
5. **Bits**: from the data start, read half-chips `a = s[pos + 0.5·spc]`,
   `b = s[pos + 1.5·spc]`; `10` → 1, `01` → 0, equal → `no mid-bit transition`. Re-anchor
   the clock on each bit's transition (searched within ±½ chip of its expected position),
   `pos = edge + spc`. Stop when the next three chip centers are all OFF (the terminating
   gap). A read exceeding `8·(2 + 255)` bits → `no terminating gap`.
6. **Checks**: fewer than 16 bits → `truncated`; bit count ≠ `8 + 8·LEN + 8` →
   `length mismatch`; CRC-8 over the first `8 + 8·LEN` bits ≠ the last 8 → `crc mismatch`.
7. **Result**: `{ ok: true, data, reverse, chipPx, leaderStart, dataStart, fieldEdges }`
   where `leaderStart`/`dataStart`/the edges are sample indices in the ORIGINAL array's
   orientation (a reversed decode's sample `i` maps back to `N − 1 − i`) — the
   GAP/LEADER/LEN/DATA/CRC boundaries plus every INTERIOR DATA byte boundary; or
   `{ ok: false, reason }` with one of the reasons above.

The kernel converts sample indices to angles (`θ = 2π·i/N`, un-reversed) so the renderer
draws the annotations in fovea px: the fitted circle, the leader arc, and radial divider
lines at every field and byte boundary. Its readout (`RingReadout`) carries the circle even
when the decode failed, so a failed frame still shows where the ring was found; the
extraction's own failure is `no ring` (circle null).

### Error recovery

There is no correction, only rejection and repetition: a frame that fails any check is
DROPPED and the emitter's next cycle is a fresh, independent read. The exposure seam
precesses around the ring across frames (two free-running clocks never match exactly), so
no chip is permanently blind. A consumer wanting a stable value votes across consecutive
successful reads; the app surfaces the LAST successful read per eye and the CURRENT
reason otherwise.

## Vectors {#vectors}

`docs/schema/codec/ring-code-vectors.json` — for each of `""`, `"\x00"`, `"H"`, `"Hi"`,
`"Hello"`, `FF 00 A5 5A`, `"Hello, world!"`: the data, LEN, CRC-8, and the full chip
string. `ring-code.test.ts` pins `encodeFrame` to them and proves `decodeRing` recovers
each under every rotation, both directions, non-integer samples per chip, and a one-sample
seam; and that a flipped bit yields `crc mismatch`, a truncated tail `length mismatch`,
and an oversubscribed ring `below resolution`.
